# F10 · QQ 机器人用户交互迭代（绑定/查单补强）· 提案

> 2026-09-10 起草。**状态：⏸ 待审核**（批准后按「四、里程碑」M1–M4 实施，版本 v3.6.3）。
> 基线：F5 双向已实施（2026-09-09，aoi-qqbot M1–M7）——bot 端已有「查单 / 我的进度 / 团况 /
> 绑定 <密钥> <圈名> / 帮助」五条指令 + 自动催缴 + 排发 xlsx 私发 + 非文本兜底；
> 网页端团员看板已有 QQ 绑定卡（填 QQ 号直写 `memberMeta[cn].qq`）。
> 本计划 = 在该基线上补齐**用户自主交互**的真实缺口，不改动 F5 已定稿的安全边界与催缴/排发链路。

---

## 一、要解决的问题（现状缺口盘点）

1. **QQ 唯一性无校验（正确性缺陷，最高优先）**：bot「绑定」与网页端 `bindQq` 都是直接写
   `memberMeta[cn].qq`，同一 QQ 可绑到多个圈名；而 `member_lookup_by_qq` 做 QQ→CN 解析时
   `limit 1` 随机命中一条——**查单/进度/自动催缴可能落到错误的人身上**。改圈名审批已迁移 QQ
   （`migrateBuyer`），不受此影响。
2. **绑错了无法自救**：bot 端无「解绑」指令；网页端绑定卡只有「绑定」没有「解绑」按钮，
   只能重绑覆盖或找团长。
3. **团员无法主动确认绑定状态**：只能发一次「查单」间接验证（未绑定会收到引导语）。
4. **查单无筛选**：订单多时一屏长文；快递单号淹没在逐条明细里，到货后团员最关心的就是单号。
5. 帮助文案未覆盖上述能力（新增指令需入列）。

## 二、功能清单（供审核）

| # | 功能 | 交互 | 通道 | 说明 |
|---|------|------|------|------|
| F10-A | QQ 绑定唯一性校验 | 绑定/保存时前置检查 | bot 私聊 + 网页 | 目标 QQ 已被**其他**圈名绑定时拒绝：「该 QQ 已绑定其他圈名，请先解绑或联系团长」（不泄露他人圈名）；绑回自己圈名 = 幂等成功。零新 SQL：复用 `member_lookup_by_qq(p_qq)` 做全局解析 |
| F10-B | bot「解绑 <团员密钥> <圈名>」 | 私聊指令 | 私聊 | 与绑定同格式防冒用；群内发解绑 → 引导私聊（沿用现有绑定保护，不落密钥）；通过后写 `memberMeta[cn].qq = ''`；密钥即用即焚（scrubBindCtx 沿用） |
| F10-C | 网页端解绑按钮 + 复制绑定指令 | 团员看板 QQ 卡 | 网页 | 已绑定态：显示 QQ + 「解绑」按钮（登录态即权限，确认弹窗后写 `qq=''`）；未绑定态：加「复制绑定指令」按钮（用 `state.key` 拼装 `绑定 <密钥> <圈名>`，粘贴给 bot 即完成**验证式**绑定——网页填 QQ 是声明式，bot 绑定顺带验证了私聊可达） |
| F10-D | bot「我是谁」 | 私聊指令 | 私聊 | 返回当前 QQ 绑定的圈名 + 团名；未绑定回引导语（沿用 unboundGuidance，不泄露存在性） |

| F10-F | 「我的快递」 | 私聊指令 | 私聊 | 只列已发订单的「制品 ×数量｜单号」；全部未发时提示「还没有已发货的记录哦」；数据源同 `member_lookup_by_qq` 的 tracking 字段 |
| F10-G | 帮助更新 | 「帮助」/「菜单」 | 私聊 | F10-B/D/E/F 指令入列 |

催缴截图审核流（涉及 admin-payment 改造，仍下期）、「我的交费」独立指令（查单已含国际费明细，避免指令冗余）、
跨团查询（单团模型不变）。

## 三、实现方案

### relay 侧（aoi-qqbot 仓库，零新依赖，单文件 relay.js 增量）

- `parseCommand` 扩展（中文裸词沿用）：
  - `^解绑` → `{ type: 'unbind', key, cn }`（参数结构与 bind 一致）
  - `我是谁` → `{ type: 'whoami' }`
  - `我的快递` → `{ type: 'tracking' }`
  - `^查单` → `{ type: 'lookup', activity: <其余文本或空> }`（带参向后兼容：裸「查单」= 全量）
- `handlers.unbind`：复用 bind 的密钥校验路径（`get_team_by_member_key(key, cn)` 且 `res.cn === cn`）
  → 通过后 `update_team_data_by_member_key(key, { memberMeta: { [cn]: { …meta, qq: '' } } }, null, cn)`
  （合并保留 memberMeta 既有字段，与 bind 写法对称）；群内触发引导私聊并 `scrubBindCtx` 置空密钥。
- **F10-A 校验（bind 内前置）**：写入前调现成 `member_lookup_by_qq(p_qq)`——返回非 null 且
  `cn !== 输入圈名` → 拒绝并提示；`cn === 输入圈名` → 幂等放行（直接回「已绑定」）。
- `handlers.whoami` / `handlers.tracking`：走现成 `lookupByQq(qq)` 三态处理（未绑定/服务异常/正常）；
  `renderLookup(lookup, activityFilter)` 增加过滤参数（`o.activity` 包含匹配，忽略大小写）。
- `helpText` 更新；限频 / 去重 / 白名单群 / 群内出口黑名单 / 审计（`unbind_ok`、`whoami_ok` 等，
  QQ 尾 4 位打码）全部沿用不动。

### 主仓库侧（v3.6.3，**零 schema 改动**，supabase-schema.sql 不动）

- `js/member.js`：
  - `bindQq` 前置冲突校验：`Aoi.db.rpc('member_lookup_by_qq', { p_qq: qq })`（anon 可执行，
    data.js 已有 `.rpc` 封装先例）；debug 账户（localStorage 模式）跳过校验。冲突 → 报错文案与 bot 端一致。
  - `renderBind` 已绑定态：QQ + 「解绑」按钮 → `Aoi.member.unbindQq()`（确认弹窗 → 写 `qq=''` →
    `persist` → 重渲染）；未绑定态：「复制绑定指令」按钮（`'绑定 ' + state.key + ' ' + state.cn`，
    `navigator.clipboard` + execCommand 降级，成功 toast）。
- `index.html`：无结构改动（QQ 卡为动态 innerHTML）。
- tests：新增 `member-qq-bind.test.js`（冲突拒绝 / 绑回自己幂等 / 解绑写空 / 复制指令拼装 /
  debug 模式跳过校验），全套 `npm test` 全绿。

### 安全评审（相对 F5 条款的增量）

1. 解绑防冒用：bot 端必须密钥+圈名双验（与绑定同级）；网页端走登录态天然免验。
2. 冲突提示不泄露他人圈名（固定文案）。
3. 「我是谁」只回圈名/团名，属本人数据，走私聊。
4. 群内出口黑名单不变：解绑/查单筛选等一切回复仍只走私聊，群内无新出口。
5. 审计打码沿用：新事件类型只记类型 + QQ 尾 4 位。

## 五、拍板结论与待确认项
