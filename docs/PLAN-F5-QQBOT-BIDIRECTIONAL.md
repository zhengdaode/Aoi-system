## 一、项目定位与边界

- **独立项目**：新仓库（建议名 `aoi-qqbot`），承载 relay v4（双向版）与配套测试；Aoi-system 主仓库
  仅在最终接入时合入一处改动（M4：3 个 Supabase RPC + 设置页扩展，见五·M4，可独立回退）。
- **不做的事**：不做群聊闲聊/关键词自动回复以外的任何自动化；不动现有单向推送链路的行为；
  不在群里公开任何成员个人数据（查单结果一律私聊回复；群内唯一例外为拍板允许的 F5-G 催缴点名圈名/@本人，金额与订单明细仍不进群）。
- **复用前提**：v3.4.0 已上线的两个后端能力是本项目的基础——
  ① `update_team_data_by_member_key(..., p_cn)` 白名单写入口（绑定 QQ 复用它，无需新写入口）；
  ② `get_team_by_member_key(member_key, p_cn)` 按 CN 裁剪读（查单数据源）。

| # | 功能 | 交互 | 回复通道 | 说明 |
|---|------|------|----------|------|

| F5-B | 私聊查进度 | 私聊 bot「我的进度」 | 私聊 | 逐批次时间线文本（排单→到货→交费→发货→收货，与网页 F2 时间线同一套节点口径） |
| F5-C | 私聊自助绑定 QQ | 私聊 bot「绑定 <团员密钥> <圈名>」 | 私聊 | 用一次性输入的团员密钥校验身份，通过后写入 `memberMeta[cn].qq`（复用 B2 白名单 RPC）；密钥即时丢弃、不落任何日志 |
| F5-D | 帮助 | 「帮助」/「菜单」 | 私聊 | 指令一览 + 网页看板地址 |

| F5-H | 文件/图片发送 | 排发/催缴流程触发 | 私聊 | ① 排发：网页端批量「设为已发」后，前端自动调 relay 生成**排发表 xlsx**（字段同 `Aoi.ship.export`）私发管理员，**转发目标 QQ 在网页端设置页配置**（存 `botConfig.adminQq`），不进群；② 催缴：私聊附缴费二维码图，**二维码在网页端上传**（复用图床 `Aoi.img`，URL 存 `botConfig.qrUrl`），网页换图后下次催缴自动生效 |
| F5-I | 非文本消息接收兜底 | 收到图片/表情/文件等 | 私聊 | 不再静默忽略：私聊非文本统一回引导语「暂时只支持文字指令，发送『帮助』查看」；群内非文本仍忽略（避免刷屏）；催缴截图上传审核流**仍不做**（涉及 admin-payment 改造，下期） |

## 三、架构（在现有链路上的增量）

```
QQ 群/私聊 ⇄ NapCat ──上行事件(HTTP POST)──▶ relay v4（ECS，同机）
                                              ├─ /             单向推送（现有，不动）
                                              ├─ /onebot/event  上行事件接收（新）
                                              │    ├─ 解析指令 → 去重/限频 → 白名单群校验
                                              │    ├─ 查数据：调 Supabase 团员 RPC（anon 身份）
                                              │    └─ 回复：经 NapCat send_private_msg
                                              └─ NapCat HTTP API（现有）
```

- **relay v4 改造**（`relay/relay.js` 同仓升级）：新增 `POST /onebot/event` 端点接收 NapCat 上行
  （NapCat 配置 HTTP POST 上报地址指向它）；事件按 `message_id` 去重防重放；文本指令解析
  （前缀「查单/我的进度/团况/绑定/帮助」，大小写与空格容错）；非文本消息按 F5-I 兜底；串行队列复用现有节流。
- **催缴定时器**（relay 内新增，独立调度模块）：`scheduler.register({ dayOfWeek, hour }, name, fn)` ——
  调度器与任务解耦，后续新增定时任务直接复用；星期与时刻走 env（`REMIND_DAY` 默认 6=周六、`REMIND_HOUR` 默认 10，均可改）。
  催缴任务 `runRemindUnpaid()` 为独立导出函数，可被定时器/测试/手动触发端点三处调用。
  每次触发调 `unpaid_members_by_group()` RPC（顺带返回 botConfig settings：二维码 URL 等）取待缴费名单
  （含 cn/qq/金额/DDL）→ 逐人**先私聊**催缴（附二维码）→ 私聊发送失败或未绑 QQ 者转群内兜底
  （F5-G：@本人 / 点名圈名，合并为一条）→ 结果写 JSONL 审计。
  同一团同一轮（同一自然日）最多触发一次，本地状态文件防重启重复发；`REMIND_ENABLED=false` 可整体关闭。
- **排发 xlsx 私发管理员**：网页端排发页「批量设为已发」后（`shipping.js` 已有该钩子位），前端带 admin token
  调 relay 新端点 `POST /onebot/export-shipping`（body：batchId + 行数据 + 目标 QQ）。
  relay 用**零依赖内置 xlsx 生成器**打包 `排发_<批次日期>.xlsx`——STORE 模式 zip + inlineStr，
  不破坏 relay 单文件零依赖部署（若验收发现兼容问题，降级方案为引入 npm `xlsx` 包）；字段同 `Aoi.ship.export`
  （购买者/制品/发货线路/数量/囤货地/快递单号/合照/状态）。目标 QQ 取 `botConfig.adminQq`（网页设置页配置，可随时改），
  经 NapCat `upload_private_file` 私发；文件先写 `os.tmpdir()`、发送成功即删。
- **二维码网页端上传与自动同步**：设置页复用图床模块 `Aoi.img` 上传二维码图，返回 URL 存 `botConfig.qrUrl`；
  relay **每次发送时实时读取**该 URL（催缴 RPC 顺带返回），CQ image 码支持远程 URL、NapCat 自行下载——
  网页换图后下次催缴自动用新图，无需任何推送即天然同步。未配置二维码时纯文本催缴。
- **新增 3 个 Supabase RPC**（主仓库，M4 时合入）：
  ① `member_lookup_by_qq(p_qq text)` —— security definer；按 `memberMeta` 把 QQ 解析到 CN 后，
  只返回该成员的订单/交费状态摘要与看板地址，**不返回整 blob、不含任何他人数据**（字段级设计见附录）；
  ② `team_summary_for_group()` —— 白名单群对应的团级聚合（阶段/计数/DDL），无个人字段，供 F5-E 团况查询使用；
  ③ `unpaid_members_by_group()` —— security definer；返回待缴费名单（cn/qq  nullable/金额/DDL）
  **及 botConfig settings（二维码 URL 等）**，供催缴任务用；不含地址、不含已缴费成员数据。
- **绑定流数据路径**：密钥+CN 校验 = 调现有 `get_team_by_member_key(key, cn)`（返回 null 即密钥/圈名不符）
  → 通过后调 `update_team_data_by_member_key(key, {memberMeta:{cn:{qq}}}, null, cn)`（B2 白名单已覆盖此写法）。
  全程不新增存储，绑定关系仍以 blob `memberMeta` 为唯一事实源（单团模型：一个部署服务一个团，不做跨团解析）。

## 四、安全与防滥用

1. **白名单群**：relay 只处理配置群号的上行 @ 消息（env `ALLOWED_GROUPS`），其他群一律忽略。
2. **限频**：每 QQ 每分钟 ≤3 条指令、每分钟全局 ≤30 条；超限静默丢弃并记日志。
3. **私聊兜底**：群内指令一律私聊回复；查不到绑定关系时回复引导语（附网页绑定地址），不泄露存在性。
4. **凭证纪律**：绑定密钥只在单条消息生命周期内存在，处理完即置空；relay 日志对该消息体打码（只记指令类型与 QQ 尾 4 位）。
5. **事件防重放/防伪造**：NapCat 上报走 `127.0.0.1`（同机 host 网络，不走公网）；`message_id` 去重（内存 + 5 分钟过期）。
6. **审计**：relay 把每次指令（类型/QQ 尾号/结果）追加到本地 JSONL 日志，供排查。
7. **群内信息最小化**（新增）：团况查询的群内回复只允许来自 `team_summary_for_group()` 的白名单字段
   （阶段/匿名计数/DDL），代码层面在「群内回复」出口做一次字段过滤；催缴兜底（F5-G）经拍板允许点名
   圈名/@本人，但金额/订单明细/地址列入群内出口黑名单，即使上游误传也发不出去。
8. **催缴防骚扰**（新增）：每 QQ 每团每日最多 1 条催缴私聊；催缴文案带「已交费请忽略」；
   群内兜底催缴每团每日合并为 1 条（点名列表一次列完，不逐人刷屏）；运营可通过 env 开关或临时文件整体暂停。
9. **文件发送安全**（新增）：排发 xlsx 仅发管理员私聊（目标 QQ 由网页端设置，可随时改）；文件先写 `os.tmpdir()`
   并在发送后删除；只发系统生成物（xlsx/二维码 URL 引用，relay 不保存二维码图片本体），
   不转发任何用户上传内容（bot 收到的文件一律不保存、不转发）。

部署动作（实施时需要你在场配合）：NapCat 开启 HTTP POST 上报（WebUI 配置）、`systemctl restart qq-relay`、
ECS 上按 M1 附带的 Caddyfile 启用 TLS 反代（relay 获得 HTTPS 域名，网页端 relay 地址改填 `https://`）、
主仓库 M4 合入后按常规重跑 schema + 部署前端。

**HTTPS 反代的目的（GitHub Pages 兼容性）**：GitHub Pages 强制 HTTPS，浏览器会拦截 HTTPS 页面对
HTTP 接口的请求（mixed content）。裸 HTTP relay 下，GitHub Pages 版网页的设置页保存、排发 xlsx 推送等
「网页发起」的调用会被拦（此限制 v3 单向推送即已存在，非 F5 新引入）；QQ 侧被动功能（查单/团况/自动催缴）
不受托管与该限制影响，任何版本下照常工作。relay 套 TLS 后，所有托管版本（GitHub Pages / Netlify / 本地）
均可使用全部功能。

## 六、拍板结论与待确认项

**已拍板（2026-09-08）**：
1. **跨团查询：不做**，维持单团模型（原跨团功能已移出范围）。
2. **催缴策略：私聊优先**——未绑定 QQ 或私聊不可达（对方关闭私聊/发送失败）者，转群内兜底催缴
   （F5-G：@本人或点名圈名，金额不进群）。
3. **催缴附缴费二维码：做**——二维码在网页端上传（存 `botConfig.qrUrl`），网页换图后下次催缴自动生效。
4. **排发表格式：xlsx**（替代 CSV），排发「设为已发」后自动私发管理员；**转发目标 QQ 在网页端设置页配置**（存 `botConfig.adminQq`）。
5. **催缴时刻：每周六上午 10:00**（env `REMIND_DAY`/`REMIND_HOUR` 可改）；调度器与任务解耦
   （`scheduler.register` + `runRemindUnpaid` 独立函数），后续新增/修改定时任务直接复用，无需改架构。

**按默认执行（原版计划已审核通过，未提出异议）**：开放 bot 私聊绑定；私聊查单含金额；白名单群先放 1 个运营群；
中文裸词指令（查单/绑定/帮助）；限频每 QQ 3 条/分钟；人设沿用「艾娃拉斯汀」，带谷圈语气（交肾/吃谷）。

**仍待确认**：无（v3 定稿，待最终批准后按 M1 开工）。

**仍不做**：催缴截图图片审核流、bot 接收并保存/转发用户上传文件。

## 附录：`member_lookup_by_qq` 返回字段设计（草案）

```json
{
  "cn": "小樱",
  "teamName": "××团",
  "boardUrl": "<网页看板地址>",
  "orders": [ { "activity": "...", "typeModel": "吧唧-A", "count": 1,
                "status": "已到货", "shipped": "未发", "received": false, "tracking": null } ],
  "fees":   [ { "batchDate": "2026-09-01", "intlFee": 12.5, "payStatus": "待审核" } ],
  "generatedAt": "<ISO 时间>"
}
```

- 只含本人条目；不含地址/QQ 原文/他人任何数据/凭证 URL。
- 与 F2 时间线同一套状态口径，便于两端一致。

## 附录 B：`team_summary_for_group` 返回字段设计（草案，仅群内白名单字段）

```json
{
  "teamName": "××团",
  "stage": "交费中",
  "totalMembers": 23,
  "paidCount": 17,
  "unpaidCount": 6,
  "deadline": "2026-09-15",
  "generatedAt": "<ISO 时间>"
}
```

- 全部为聚合字段，无任何个人标识；relay 侧群内出口以此字段白名单做二次过滤（安全条款 7）。
