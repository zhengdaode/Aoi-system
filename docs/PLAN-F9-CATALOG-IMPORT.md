# F9 · 商品目录抓取导入 + 补货监控 —— 可行性评估与实施计划（v3.7.0 提案，待审核）

> 评估日期 2026-09-09。目标工作流：宝可梦官网商品目录 → 半自动批量建品 → 自动翻译中文名 + 自动匹配商品类型 → 人工校对 → 按小程序格式生成表格 → 上架小程序 → 小程序拼团情况回流。
> 实测样本：「Pokémon Magic Hour Illusion!」情报页（`/goods/2026/09/260904_to01.html`，28 件商品）+ PCO 搜索页（`q=9月10日発売`）。

## 0. 结论速览

| 评估项 | 结论 | 依据（2026-09-09 实测） |
|---|---|---|
| 翻译是否必须接 AI | **不必须**。词典法为主，机翻/LLM 仅作可选兜底 | 宝可梦商品名高度模式化（品类词＋宝可梦名＋系列名）；PokeAPI 免费提供官方 zh-hans 译名（已实测）；人工校对环节本来保留 |
| 情报站 pokemon.co.jp 抓取 | **可行**（主数据源） | HTTP 200、纯静态 HTML 59KB、robots.txt 放行 `/goods/`、商品表格解析锚点干净 |
| 购买站 pokemoncenter-online.com 抓取 | **服务端不可行**，只做「商品名→搜索链接」拼接 | 全站 JS 反爬：任意页面 302 → `wr.pokemoncenter-online.com` 质询 → 非浏览器客户端陷入 50 次重定向死循环（实测，含首页） |
| 补货监控 | **可行**。一期做被动 diff，二期可选定时推送 | 官网无 RSS（404）；`/goods/` 列表页 200 可 diff；通知可复用 F5 QQ 链路 |

## 1. 目标工作流 → 系统能力映射

| 你的步骤 | 承载能力 |
|---|---|
| 1. 识别网站商品目录文本 / 粘贴目录链接 | **S1**：情报页 URL 经 ECS relay 抓取解析；「全选复制页面文本粘贴」为永远可用的兜底入口 |

| 4. 人工检查问题并修改 | **S3**：校对工作台表格（中文名 / 类型 / 价格 / 参考图 / 链接均可编辑） |

## 2. 实测记录（2026-09-09）

### 2.1 情报站 pokemon.co.jp —— 主数据源 ✓

- 状态：`200 text/html 59KB`，纯静态，无反爬。
- robots.txt：`Disallow` 仅限 `/img/`、`/resource/`、`/common/` 等静态资源路径，**`/goods/` 放行**——自动抓取只取文本元数据，商品图片走人工上传（v3.6.1「添加图片」弹窗），合规且省事。
- 解析锚点（真实 HTML 结构，极干净）：

```html
<tr><th>発売日</th><td>9月12日（土）<br><span>※ポケモンセンターオンラインでは、9月10日（木）10時より…</span></td></tr>
<tr><th>商品詳細</th><td>
  <span class="m-text-bold">ぬいぐるみ Pokémon Magic Hour Illusion! ピカチュウ</span>　3,960円<br>
  <span class="m-text-bold">マスコット Pokémon Magic Hour Illusion! ゾロア</span>　1,980円<br>…
</td></tr>
<tr><th>販売店舗</th><td>…</td></tr>
```

- 一次情报页可完整提取：**商品名 + 含税价格（逐行）+ 発売日 + 贩售渠道**。样例页 28 件全部可提取。
- 文本兜底：页面文字全选复制后每行形如 `名称　X,XXX円`，正则 `^(.+?)[\s　]+([\d,]+)円` 即可逐行解析，不依赖任何网络通道。

### 2.2 购买站 pokemoncenter-online.com —— 只做链接拼接 ✗

- 搜索页与首页对非浏览器客户端一律 `302` → `wr.pokemoncenter-online.com`（JS 质询页）→ 回跳，**curl 跟随重定向陷入 50 次死循环**，永远拿不到内容。
- 结论：**不做 PCO 服务端抓取，也不尝试绕过反爬（合规红线）**。PCO 的用途是：按商品名 URL-encode 生成搜索直达链接，填入 `refUrl` 字段，管理员点击即可人工核对/下单。

### 2.3 翻译数据源 PokeAPI —— 官方中文名 ✓

- `https://pokeapi.co/api/v2/pokemon-species/{id}` 免费无 key，含 `zh-hans` 官方译名（实测皮卡丘 → `皮卡丘`，每种约 10 条中文条目）。
- 用法：**一次性脚本拉全量（约 1025 种）生成 `ja → zh-hans` 词典 JSON 提交入仓**，运行时零外部依赖、零成本、不受国内网络影响。

## 3. 评估一：翻译是否必须接 AI？

**不必须。** 宝可梦商品名是「品类词 + 系列名 + 宝可梦名」的有限组合，词典法的效果反而优于通用机翻（机翻会把片假名种名音译，而词典给官方中文名）。分三层：

| 层 | 方式 | 成本 | 定位 |
|---|---|---|---|
| L0 词典 | ①品类词表（~60 条，如 `ぬいぐるみ→毛绒玩偶`、`アクリルスタンド→亚克力立牌`、`缶バッジ→铁皮徽章`）②宝可梦官方中文名表（PokeAPI 预生成入仓）③杂项词表（`マグカップ→马克杯` 等，可在设置页自定义扩充，存 blob） | 零 | **主力**，预估覆盖 80–95%，未识别片段高亮，人工补 |
| L1 免费机翻 | Google 非官方端点，经 relay 服务端调用 | 零（不稳定） | 可选兜底，仅出草稿 |
| L2 LLM 精修 | 设置页自配低成本 key（DeepSeek/GLM 等），整批一次调用，翻译未识别片段并建议品类 | 极低 | 可选增强；无 key 自动跳过 |

真实样例（L0 效果）：

- `ぬいぐるみ Pokémon Magic Hour Illusion! ピカチュウ` → `毛绒玩偶 Pokémon Magic Hour Illusion! 皮卡丘`（系列英文名按圈内外语习惯保留原文）
- `マスコット Pokémon Magic Hour Illusion! ゾロア` → `挂件 Pokémon Magic Hour Illusion! 索罗亚`
- `もっちりパンケーキ風ポーチ` → 词典命中「ポーチ→收纳包」，其余片段高亮待人工/LLM

**建议：v3.7.0 只做 L0 + 未识别高亮；L1/L2 留接口不做。**

## 4. 评估二：网络爬虫（分站结论）

| 站点 | 结论 | 说明 |
|---|---|---|
| pokemon.co.jp 情报页 | ✓ 抓取源 | 经 ECS relay 抓取（国内网络可达性顺带解决） |
| pokemon.co.jp 商品图片 | ✗ 不自动抓 | 图片在 robots `Disallow` 路径下，走人工上传图床 |
| PCO 全站 | ✗ 不抓 | JS 反爬实测不可达；仅生成搜索直达链接 |

**通道改造需求**（这是本计划唯一的线上依赖）：

- `relay/relay.js` 的 `FETCH_HOSTS` 白名单目前只有 `static.zwlhome.com`，需**加入 `www.pokemon.co.jp`**（ECS 部署者操作 + 重启）。
- 新模块自带轻量抓取函数（Edge relay `/fetch/<host>/<path>` → 直连兜底），**不复用** `import.js` 的 `fetchFromUrl`——它把 `content-type: text/html` 判为「通道不可用」直接跳过（`js/import.js:303`）。
- `/media-proxy`（Netlify 重定向）host 写死为 `static.zwlhome.com`，不适用，无需改动 netlify.toml。

**合规边界**：低频手动触发（不做无人值守高频轮询）、仅取文本元数据、遵守 robots.txt、注明信息来源、只服务内部排单、**不自动下单**。

## 5. 评估三：补货监控

宝可梦的补货/再贩情报确实发布在官网（ニュース + 各情报页更新），方案分两期：

- **一期·被动 diff（推荐，纳入 v3.7.0）**：活动可绑定监控 URL 列表（`d.activityMeta[活动].watch = [{ url, label, lastDigest, lastCount, checkedAt }]`），工具页「检查更新」按钮经 relay 抓取，与上次快照比对指纹（詳細区条目数 + 名称串哈希）；有变化 → 提示「新增 N 件」并一键进入 S1 导入流程预填。零新增基础设施，与 S1 共用通道与解析器。
- **二期·定时推送（可选，v3.8.0 另立项）**：GitHub Actions cron（仓库已有 Actions 基建，public 仓库免费）每日抓 `/goods/` 列表页 diff，发现新情报页 → 经 aoi-qqbot relay 私发管理员（复用 F5 已建链路）。依赖 Actions 与 ECS relay 在线，且需 aoi-qqbot 侧配合，故单独评估后再做。
- **PCO 站内库存/缺货状态：不自动化**（反爬 + 需登录态，人工看）。

## 6. 实施方案（v3.7.0）

新增模块 `js/catalog.js`（目录导入，挂 `Aoi.catalog`）；词典 `js/catalog-dict.js`（品类 + 杂项，入仓可维护）+ `js/species-zh.json`（PokeAPI 预生成种名表）；页面入口放「工具」菜单。

| 项 | 内容 | 关键点 |
|---|---|---|
| S1 抓取解析 | 情报页 URL / 粘贴文本双入口 → 解析出 `[{ jpName, price, releaseNote }]` 预览 | 锚点：`<th>商品詳細</th>` 行 `<span>名称</span>　价格円`；解析器对改版容错（锚点缺失时回落整页文本正则） |
| S2 翻译与类型匹配 | L0 词典产出中文名草稿；品类中文 ↔ `d.typeMeta` 已有类型名匹配（精确/包含），未命中留空并高亮未识别片段 | 词典置信度标注；类型建议不自动新建类型 |
| S3 校对工作台 + 入库 | 表格编辑（中文名 / 类型 / 价格 / 参考图 / PCO 搜索链接），写入目标选已有活动或输入新活动名（`ensureActMeta` 兜底） | `activityMeta.products` 结构扩展可选 `price` 字段（日元，向后兼容，现有读取方不受影响）；PCO 搜索链接填 `refUrl`，参考图走 v3.6.1 图片弹窗 |
| S4 小程序表格导出 | 先出「通用全字段 xlsx」（中文名/日文名/类型/价格/参考图/链接/备注）；列映射模板（字段勾选 + 表头改名 + 顺序）存 blob，模板引擎复用 SheetJS + `exportBaseName` 文件名规则 | **模板字段依赖你提供的小程序导入样例**（见 §9）；样式复用 v3.6.0 S5 导出基建 |
| S5 被动监控 | 见 §5 一期 | 复用 S1 解析器做指纹 |

**测试**：解析器用真实页面裁剪的 HTML fixtures（`tests/fixtures/`）；词典映射、类型匹配、模板生成、watch 指纹 diff 各补单测；`tests/helpers/aoi.js` MODULES 列表按 index.html script 顺序插入 `js/catalog.js`。预估新增 40–60 用例。

**预估体量**：catalog.js 约 600–800 行 + 词典/种名表数据文件；一个活动约 30 商品，blob 增量可忽略。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 官网改版导致解析失效 | 宽松锚点 + 「粘贴文本」入口永远可用（不依赖网络通道）；fixtures 测试锁行为 |
| 词典遗漏 → 翻译不准 | 未识别片段高亮 + 设置页自定义词典扩充；人工校对本来就是流程一环 |
| relay 不在线 / 未加白名单 | 报错分级（通道不可用 vs 页面解析失败）；直连兜底；ECS 部署是前置动作 |
| PCO 反爬升级 | 不受影响——本就不抓 PCO，只拼链接 |
| 小程序模板未知 | S4 先上通用导出，模板化等样例到位再做 |
| 合规 | 见 §4 合规边界；不动 PCO 反爬，不做自动下单 |

## 8. 版本切分建议

- **v3.7.0**（本计划）：S1 + S2（仅 L0）+ S3 + S4 通用导出 + S5 被动监控。
- **v3.8.0 候选（另立项再评估）**：S4 小程序模板化导出（等样例）、定时监控 + QQ 推送（等 aoi-qqbot 配合）、L1/L2 翻译增强。

## 9. 待拍板的开放问题

1. **目标小程序是哪个？能否提供一份现有「商品导入模板」xlsx 样例？** —— S4 模板字段的唯一来源；给不了就先用通用导出人工粘贴。
2. **小程序导出的「拼团情况」表格样例** —— 决定回流方向是否需要新增模板化解析（现有 import.js 已能吃排谷表/汇总表直链）。
3. **L1/L2 翻译增强本期是否要做？** 建议不做：L0 词典 + 人工校对够用，且零成本零依赖。
4. **二期定时监控是否立项？** 涉及 GitHub Actions cron + aoi-qqbot relay 私发管理员，建议一期被动 diff 跑顺后再定。
5. **relay 白名单加 `www.pokemon.co.jp` 的部署窗口** —— 需部署者在 ECS 修改 `relay/relay.js` 的 `FETCH_HOSTS` 并重启；这是 S1 的唯一线上前置动作。
